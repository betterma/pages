## 1. 当前合约这边在干什么（目标）

把 **合约三栏页**（`futures/index.html` + `futures/fut-app.js`）的 **置顶 / 自动盯 / 雷达** 交互与 UI，对齐现货钉子页（`kline.html` 钉子抽屉），在数据仍走 `futures/*` JSON / 合约云函数的前提下，做到：

- 置顶：单击只高亮；长按出浮层；双击刷新；钉钮逻辑与钉子一致  
- 自动盯 / 雷达：底部操作栏（置顶 + 刷新），样式贴近 `card-focus-bar`  
- K 线绘制、荧光绿、自动盯线、guest/临时查看、渐进 paint 等此前已有对齐工作  

**本交接重点**：操作栏 / 长按浮层 / 多选栏 / 钉菜单 / CSS 位置与交互；以及「记一笔」是否已拆。

## 4. Agent 自认已落地的「有效」改动（相对靠谱的部分）

这些与用户明确诉求或钉子真实行为大体一致，接手时可当作「已改代码」基线再验：

### 4.1 置顶交互

- 置顶单击：只高亮 / 再点取消；**不弹底栏**  
- 长按：浮层；时长对齐钉子实值约 **450ms**  
- 双击：刷新 + 名称闪动；应保留高亮（曾修过「双击清焦点」）  
- 浮层定位：按行矩形居中（后改为主行+`.fut-sub` 合并高度）  
- 浮层内容最终应对齐钉子长按：**× / 便签**（合约无买卖）；置顶/常看走钉钮，不进长按浮层  
- `pointer` + 禁 contextmenu；名称复制走捕获阶段  

### 4.2 钉钮点击（用户纠正后）

- **已置顶或常看** → `openPinMenu`  
- **否则（其余 ↑）** → **直接 `pinToBoard`，不开菜单**  
- 已从「未置顶菜单」里撤掉误加的「取消置顶」

### 4.3 自动盯 / 雷达底栏

- 置顶 scope 不显示 `futFocusBar`  
- 自动盯 / 雷达：名称 + 置顶 + 刷新；毛玻璃 pill 样式向 `card-focus-bar` 靠  
- 自动盯行 focus：inset 描边（相对置顶行铺底）  
- 底栏名称可复制  

### 4.4 多选栏

- 从 viewport `fixed` 底栏改为贴在置顶 pane 列表底 **流式**（对齐 `.nail-batch-bar`）  
- 按钮文案带 `(n)`、主色/危险色、「取消」等  

### 4.5 其它样式 / 流程

- 币名强调色 / `cursor: copy`；钉钮 26px  
- 刷新抖动补关键帧  
- 进多选清焦点/浮层；切 tab 关焦点/浮层  
- `render()` 前关浮层与钉菜单（对齐钉子 unmount 思路）  
- 新增表单 CSS / placeholder 向 `.nail-form` 靠  
- 空态文案曾改为「还没有钉子」  

### 4.6 记一笔（现货，用户问过）

- **未物理删除**；`MOM_NOTES_FEATURE = false`；云 `MOM_NOTES_AUTO_WRITE` / `NOTES_RANK_SNAP_ENABLED` 默认关  
- 钉子 `note/noteAt` 保留

## 6. 用户指出的错误 + Agent 自知的读码错误

### 6.1 已确认的读码错误

1. **钉菜单「其余段有取消置顶」**  
   - Agent 只读了 `openNailPinMenu` 的 HTML 拼装 else 分支，**没读点击分发**：  
     `is-on || always → 开菜单`，否则 `toggleNailPinned` / guest 直接钉。  
   - 导致错误结论、错误实现、错误交接解释；被用户实测打脸。

2. **「对了十遍」可信度**  
   - 用户明确不相信。十轮列表里混有真问题、次要问题、**不存在的问题**。  
   - 根因倾向：用「菜单构建」代替「事件路径」；用「CSS 有没有」代替「用户实际看到的交互」。

### 6.2 用户怀疑「还有很多看错」——接手建议优先复查（高风险）

请 WorkBuddy **不要假设下列已正确**，请对照 `kline.html` **点击/长按路径**实测：

1. **长按浮层按钮集**  
   - 现应仅 ×/便签；是否还残留置顶/常看入口；遮罩/定位是否抖、是否跟手指。  

2. **单击 / 双击 / 长按**  
   - 是否与钉子一致（高亮、刷新、不误开底栏）。  
   - `render()` 开头 `closeFloatMenu()` 是否导致刷新/paint 时浮层被误关过频。  

3. **钉钮**  
   - 是否已与钉子一致：其余直接置顶；已置顶/常看才出菜单。  
   - 菜单项是否与钉子一致（置顶排第一 / 常看 / 取消置顶 等）。  

4. **自动盯 / 雷达底栏**  
   - 按钮是否只要置顶+刷新；位置/宽度/毛玻璃是否真的接近钉子 autopin scope。  

5. **多选栏**  
   - 流式贴底是否在真实手机上正确；是否仍有旧 fixed 残留。  

6. **记一笔**  
   - 用户问的是「去掉没」：现状是 **门闩关**，不是删光；若用户要的是删代码，尚未做。  

7. **空态文案改成「还没有钉子」**  
   - 是否抹掉了合约有用的引导文案（产品是否接受）。
