# 盯一下 / 持仓 · 企业微信推送

定时事件函数：每 5 分钟读取 GitHub 的盯一下与持仓，拉币安现价，推到企业微信群机器人。

## 推送内容

1. **盯一下**：只推 **当前 4h 窗口上涨** 的盯一下币（与 K 线页一致；可低于盯住价）  
   - 可用 `PIN_WINDOW_INTERVAL` 改窗口周期  
   - 窗口未涨的不推（页面进右侧隐藏抽屉，企微不发）  
   格式：时间 +「名称 24h%」+「【盯涨幅】」+ 盯住价 + 现价（较上次涨则 `@@@`）  
2. **短线抬高高亮**（只看已收盘 K 线，`收盘 > 前收`；只给币种名上色）：  
   - 最近 **3 根 5m 连续抬高** → 名称 **绿色**  
   - 最近 **3 根 15m 里至少 2 根抬高** → 名称 **橙色**  
   - 两者都满足 → 名称 **绿色**  
   - 文末单独一节 **5m**：只列符合 5m 三连抬高的币名（绿色，无则整节不显示）  
3. **相对上次推送**：现价高于该币上一次盯一下消息中的现价时，现价后缀 `@@@`  
4. **上涨名单** 按盯幅取前 **20** 条文字推送（可用 `PIN_NOTIFY_MAX` 改）；再合成一张竖向长图，默认最多 **12** 格（`PIN_CHART_MAX`，可用 `PIN_CHART_TOP` 再收紧）  
   - 超限时文案抬头写 `推送 n/总数`  
   - 图上标题颜色与文字一致：5m 连阳绿 / 15m 热橙  
   - 右上角标：`5M`、`15M`、`@@@`（有则显示）  
5. **持仓**：每轮定时都会推买入价→现价（与是否跌破无关）；跌破买入价 **5%** 时在文末附加告警（同币 **2 小时**冷却）  
   - **先发持仓、再发盯一下**（盯一下动量/拼图失败或超时，不能挡持仓的 5 分钟推送）

无盯一下上涨且无持仓时，不发空消息。排序以盯住涨幅为准。

可选环境变量：`PIN_NOTIFY_MAX`（默认 `20`）、`PIN_CHART_TOP`、`PIN_CHART_MAX`（默认 `12`）、`AUTO_PIN_ENABLED`（默认 `1` 云端自动盯）、`AUTO_PIN_WECOM`（默认 `1`，新自动盯仍发一条短企微；主反馈在网页日志/置顶）、`OBS_DATA_URL`、`NOTIFY_DEBOUNCE_MS`、`MOMENTUM_CONCURRENCY`。

**云端自动盯 / 回暖**：每轮在推送前读取 OBS `watch-data`，识别「观察池 ∩ 窗口上涨」边沿（相对 `risingZoneSnap`）：
- **新人**（未盯）→ 写入 `watch-pins.json`（`source: auto-cloud`）
- **回暖**（已盯）→ 按现价重钉、`source: auto-rewarm`，置顶 12h
- **同币冷却**（默认 **12 小时**，`AUTO_PIN_EDGE_COOLDOWN_MS`）：距上次盯入过近则只更新快照、不改盯入价，避免窗口抖动反复重钉
事件写入 `watch-notify-state.json` 的 `autoPinEvents`，网页打开即可看到。

**若出现「一整套消息连发 4 遍」**：先检查函数是否挂了多个定时触发器；代码已加 90 秒去重锁。务必把超时调到 ≥60～120 秒（全量拼图 + 动量 K 线更耗时）。

**若「盯一下还在、持仓/预警停了」**：多半是旧逻辑先发盯一下拼图把超时/限频吃光。当前版本已改为持仓优先，并隔离盯一下发送失败；重新部署本目录即可。

## 企业微信机器人（一次配置）

1. 打开 [企业微信](https://work.weixin.qq.com/) 并登录（个人可创建企业）  
2. 建一个群（可以只有自己）  
3. 群设置 → **群机器人** → 添加 → 复制 Webhook 地址  
4. 两个群各复制 Webhook，分别填 `WECOM_WEBHOOK_PINS`、`WECOM_WEBHOOK_POSITIONS`（或临时共用 `WECOM_WEBHOOK_URL`）

手机安装企业微信，打开消息通知；可选在「微信插件」里接收提醒。

## 部署

1. 上传本目录，Handler：`index.handler`，Node.js 18+  
2. **超时时间建议 ≥ 60～120 秒**（拼图 + 5m/15m 动量 K 线较慢；超时过短会导致平台重试，表现为同一轮连发多遍）  
3. 添加**一个**定时触发器：`0 */5 * * * *`（每 5 分钟）  
4. 环境变量：

| 变量 | 必填 | 说明 |
|------|------|------|
| `WECOM_WEBHOOK_PINS` | 二选一* | **盯一下**群机器人 Webhook |
| `WECOM_WEBHOOK_POSITIONS` | 二选一* | **持仓/购入**群机器人 Webhook |
| `WECOM_WEBHOOK_URL` | 否 | 兼容旧配置：上面两个都没填时，两类都推到这个地址 |
| `GITHUB_TOKEN` | 是 | 读 pins/positions，写 notify-state |
| `GITHUB_REPO` | 否 | 默认 `betterma/pages` |
| `DROP_THRESHOLD` | 否 | 默认 `0.05`（-5%） |
| `DROP_COOLDOWN_MS` | 否 | 默认 `7200000`（2 小时） |

\* 至少配置一个可用 Webhook；双群请分别配置，且 **不要** 把同一个消息推送/机器人加进两个群。

## 双群用法

1. 建两个内部群，例如「盯一下」「持仓」  
2. **各建一个独立的**消息推送/机器人（两份不同的 Webhook，`key=` 不同）  
3. 云函数环境变量：  
   - `WECOM_WEBHOOK_PINS` = 盯一下群  
   - `WECOM_WEBHOOK_POSITIONS` = 持仓群  
4. 若仍保留旧变量 `WECOM_WEBHOOK_URL`，建议删掉，避免和上面混用搞不清  
5. 重新部署后：上涨盯一下（文字 + Top3 图，共最多 4 条）只进第一群；持仓文字只进第二群  

若两个群同时都收到「文字+3 张图」，通常是：两个环境变量填成了同一个 URL，或同一个机器人被加进了两个群。

## 数据文件（GitHub）

| 文件 | 来源 |
|------|------|
| `watch-pins.json` | K 线页「盯一下」 |
| `watch-positions.json` | K 线页长按「购买 / 卖出」 |
| `watch-notify-state.json` | 本函数写入跌破告警冷却、上次推送价、**最近一次盯一下文案**、**最近一次持仓文案**（供 K 线页浮层） |

## 页面操作

K 线长按卡片 → **购买**（录入买入价，默认当前价）/ **卖出**（清除持仓观测）。
